# W7 现场材料包

W7 的软件演练已经通过，但真正的现场验收必须由项目外的新操作者、真实数据来源负责人、
研究接收方和独立审查人完成。本目录提供不含患者数据、映射、密钥或登录凭据的结构化模板：
[`w7-field-evidence.template.json`](field-evidence/w7-field-evidence.template.json)。

## 使用方式

1. 复制模板到受控的现场证据存储，不把填好的版本提交到公共仓库。
2. 每个条目只记录责任角色、范围、观察时间和证据引用；证据引用应指向机构自己的受控记录。
3. 不写入患者姓名、DICOM 路径、原始 UID、假名映射、密钥、口令或访问令牌。
4. 现场只在所有五个条目都有独立证据后，把对应状态改为 `accepted`，并将
   `field_acceptance_complete` 改为 `true`；工具会核对这两个事实是否一致。
5. `release_authorized` 始终由独立的发布审批流程决定，现场材料验证器不会替它授权。

验证模板：

```sh
python3.12 tools/verify_field_evidence.py \
  --input docs/field-evidence/w7-field-evidence.template.json
```

模板应输出 `field-evidence-incomplete`。任何缺项、未限定范围的 `accepted`、敏感字段名或
错误的完成标志都会失败。`requires_field` 表示尚未取得主体证据，不是失败，也不能在申报
材料中写成生产完成。

## 五项现场验收

**真实来源授权。** 记录来源系统、数据控制者、授权用途、保留期限、输入完整性和可追溯引用。
合成样例、公开下载文件或实现者口头说明不能代替来源授权。

**研究接收。** 由接收系统负责人独立导入受支持的 `ct-classic-research-v1` 数据，核对研究所需
的体素、HU、排序、几何和引用关系，并保留拒绝行为。该项不等于临床诊断适用性。

**新操作者。** 操作者不参与实现，按[运行手册](OPERATIONS.zh-CN.md)完成检查、计划、运行、
复核、发布、接收、取消和恢复；观察人记录其是否能独立解释失败与边界。

**独立隐私与可用性审查。** 分开记录隐私结论和研究可用性结论，列出未检查的像素文字、
未支持的 SOP/压缩格式和剩余风险。签名有效、OCR 阴性或像素未检查都不能单独作为隐私通过。

**持久化与灾备。** 记录受支持的文件系统、权限、备份对象、密钥恢复方式、RPO/RTO 和演练结果。
进程恢复成功不代表主机或磁盘损坏后的灾备目标已经达成。
