## 执行原则

- 沿用原 MoonBit 项目和历史；核心 DICOM 行为继续在 MoonBit 中实现。
- 测试状态以具体源码版本和运行结果为准。
- 跨文件系统事务、密钥与隐私门槛不能用普通文件存在或摘要成功代替。
- 当前阶段未完成验收之前，不宣称整个 P0–P7 已完成。

## P0 证据

- 新增 6 项 Native 测试；本轮 Native 97/97 通过。
- `tools/verify_system_failures.py` 验证实际双进程同目标竞争、SIGKILL、内核 EFBIG 写入失败、父目录别名、硬链接和权限失败。EFBIG 不能当作真实 ENOSPC 证据。
- `tools/benchmark_resources.py` 对 1/16/64/120 MiB 合成载荷各测量五次；native 子进程 RSS 与生成/对照 Python 进程分离。
- 120 MiB 对象记录峰值约 491 MiB，仍不是有界流式路径；该结果用于后续改造对照。
- 支持 SV/UV 的扩展长度头和八字节值单位，其他二进制 VR 单位检查；文本长度改为 Unicode codepoint 计数。
- Unix 源句柄和路径身份复核、单链接约束；Windows 路径/链接检查并未提供同等句柄身份认证。
- 证据：`docs/evidence/p0-system-failures.json`、`docs/evidence/p0-resources.json`。后续代码变化需要重新记录与对应源码绑定。
- 跨平台修复 `671ffa1` 已通过 Linux/macOS/Windows CI：运行 `38048712435`。

## P2 证据

- MoonBit 核心通过私有 IPC 使用 SQLite/HMAC/HKDF/AES-GCM 适配；无自行实现密码算法。
- 合成三批导入、八个并发预留、域隔离、内容/归属/患者冲突回滚、错误/缺失密钥、轮换与备份恢复检查通过。
- 包装密钥采用不可变代次与原子 CURRENT 切换；保留旧代次，映射不改变。
- `PERSISTENT_IDENTITY.md` 说明 POSIX 本机提供方、备份包含密钥以及未达成的 P2 门槛。

## P3 证据

- `RECOVERY.md`、`tools/verify_recovery.py` 与 `evidence/p3-recovery.json`；不把进程强杀等同断电认证。

## P4 证据

- 企业入口采用 MoonBit 元数据前缀/像素跨度、有界复制和增量摘要；回读及恢复也走流式路径。
- 1/16/64/120 MiB 各五轮，120 MiB 峰值约29 MiB，相对 P0 约491 MiB；像素摘要逐次保持一致。
- 1,000 小对象峰值约35 MiB、10,000 小对象约164 MiB，后者约89秒；合成小像素计数负载不能代替32GiB真实负载。
- Native102/102 与其他三个后端各53项通过；P2/P3 集成回归通过；P2/P3 远端跨平台 CI 成功。
