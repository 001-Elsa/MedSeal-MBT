# W7 操作者演练与现场证据边界

`tools/verify_w7_rehearsal.py` 运行现有企业入口的完整合成演练：首次全量、两批
新增随访、纯重复交付、历史内容冲突、SIGKILL 后恢复、包装密钥轮换与备份恢复、
签名包独立验签和幂等接收回执。它把脚本输出保存为可追溯 JSON，并把真实现场
材料单独列成 `requires_field`，不会把合成脚本代替真实操作者或真实接收方。

```sh
python3 tools/verify_w7_rehearsal.py --record tmp/w7-rehearsal.json
```

## 新操作者清单

现场操作者应在没有修改源码、没有读取私有映射或密钥、只按照
[`OPERATIONS.zh-CN.md`](OPERATIONS.zh-CN.md) 的前提下完成：

1. 检查 `doctor` 输出和受控工作区权限，创建首次作业并确认发现/排除计数。
2. 执行计划、运行、独立风险复核、签名发布和接收验签；把作业 ID、状态和回执关联起来。
3. 对新增随访、纯重复批、冲突批、策略变更、取消和强杀恢复记录失败原因与可交付范围。
4. 轮换包装密钥并从备份恢复，再确认既有假名/UID/时间关系没有变化。
5. 单独记录真实来源授权、研究接收用途、独立隐私/可用性审查和文件系统灾备结果。

软件演练完成只证明受控合成路径的 M1 性质；真实来源、责任人、接收系统和独立评审
仍是 W7 的 M3 材料。没有这些主体证据，`field_acceptance_complete` 必须保持 `false`。
