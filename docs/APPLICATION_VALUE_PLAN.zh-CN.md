# 以实际任务验收的下一轮升级计划

制定基线：C1 `e0b12bf` / C2 `1b03918`。已完成公开集合 SDK、离线合成实验室及三平台 CI；C2 浏览器实际渲染/CSP 强制执行仍待验。本计划细化[社区路线图](COMMUNITY_ROADMAP.zh-CN.md)，继续同一项目，不把新增源码当作已发布 0.2.3 的能力。

## 1. 优先服务的三个实际任务

| 使用者与任务 | 当前使用障碍 | 目标交付与衡量方式 |
| --- | --- | --- |
| MoonBit 开发者把既有研究系统的影像元数据接入自己的程序 | 只有二进制入口，外部工具常用 DICOM JSON；自行转换易丢失多值、PN、整数或序列 | 公共 DICOM JSON 编解码，明确子集、拒绝不支持形态；pydicom 双向验证；仅公开 API 的可运行集成示例 |
| 研究人员从原始数据准备一批可用的 CT 数据 | 合成测试不能证明来源数据适用；需要发现、清单、计划、失败修复与接收复核 | 先建立数据集预检报告和逐对象拒绝原因，再验证授权 phantom/指定来源；接收端重算像素、HU、几何和引用；所有实际数据的许可/来源可查 |
| 本地管理员重复执行、升级、交付并处理失败 | 工具入口多、部署依赖较重；旧作业与新版程序指纹绑定 | 引导式本地流程、环境预检、一键合成验收、版本兼容/迁移检查、恢复演练；新目录照文档运行，不依赖作者机器隐式状态 |

优先级：先打通可独立验证的标准数据交换，再做数据集预检和真实接收。先提供可复用的库能力，而不是给没有现场证据的服务贴“企业级”标签。

## 3. 其他维度的改进

- **准确性：** 明确 DICOM JSON 编解码与严格影像验证是不同操作。能解析 JSON 不表示 IOD 合格或完成脱敏。拒绝 unsupported 输入，不通过猜测转换 VR、网络下载或忽略字段来制造兼容。
- **隐私：** 标准 JSON 可以含身份与像素，是私有数据交换格式；继续用 `api/explain`/受限报告做公开解释。新接口异常不拼接原值、原路径或 JSON 内容。
- **可维护性：** 用版本化支持矩阵、独立预期和回归消费者约束 API。新协议只落在一个 MoonBit 实现中；Python 负责独立预期与宿主 I/O，页面负责呈现。
- **可重现性：** 验收绑定源码/夹具/工具链摘要，临时输出与历史发行物分开保存。缺少依赖或夹具必须失败，不静默跳过。
- **社区采用：** 提供十分钟可运行的嵌入示例、问题复现模板和适合新贡献者的边界明确任务。实际采用与反馈仅记录真实取得的材料；不自动联系第三方。
- **参赛表达：** 每项亮点给“使用场景—操作—输出—独立验证”四步证据；指标来自实测，不以总代码量、测试运行次数或假想客户数量证明价值。

## 4. V1 的实现边界

首版只处理**单个 Dataset 对象**：大写八位 Tag、`vr`、`Value`、`InlineBinary`，支持选定文本 VR、PN 三表示组、DS/IS、US/SS/UL/SL、SQ，以及 OB/OW/UN 的内联二进制。不接受 HTTP URI、不下载 BulkData、不实现查询/存储协议；DICOMweb JSON 可作为适配层输入，但不是完整 DICOMweb 客户端。

DS/IS 保留合法数值字符串，不通过 Double 改写高精度十进制；数值 JSON 输入只在所承诺范围内接受。64 位整数和浮点数组在首版必须明确拒绝，避免现有 DataSet 原始字节表示与 JSON 数值的错误对应。支持矩阵和测试通过后再扩张。

预算先设为：JSON UTF-8 8 MiB、Sequence 深度 16、全树 20,000 Dataset/元素/值/条目、单个内联二进制 1 MiB；先检查文本长度/嵌套/重复键，再构建数据集。编解码不读写任何路径、不授权发布。
