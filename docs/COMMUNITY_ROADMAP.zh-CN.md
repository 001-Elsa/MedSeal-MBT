# MedSeal 社区价值升级：从内部工具到可复用的 MoonBit 影像基础设施

制定基线：0.2.3 / `5555225`。本方案继续原仓库，承接 W0–W7；不把旧阶段的通过记录用于证明新增功能。目标是降低其他 MoonBit 开发者处理医疗二进制格式、验证转换和构建离线应用的成本。获奖取决于评审；工程目标用可运行产物验收。

## 1. 重新判断差距

现有优势是严格的限定范围、关联对象处理、恢复和审核链。主要不足是：

1. **公共库还不能顺畅完成实际任务。** 原仓库外消费者只编译策略，转换需要调用内部 identity Context。库有门面，不等于开发者拿到完整工作流。
2. **评审和新用户无法快速体验核心价值。** 本地工作台依赖 Python/Native/私有状态；缺少直接运行 MoonBit 核心的浏览器入口。
3. **标准支持仍窄，外部生态联通不足。** 已有小型固定语料与 pydicom 验证，但不能据此声称支持一般 DICOM 工作负载。
4. **社区资产的复用方式不够清楚。** 规则、语料、诊断和输出校验应能独立接入别人的程序，而非必须照搬整个企业宿主。
5. **缺少真实第三方使用反馈。** 自己跑的消费者、合成演练与真实部署需要分别记账，不能互相替代。

对标依据沿用[13 项固定源码研究](WINNER_RESEARCH.zh-CN.md)：MoUI 的外部消费者、MoonFrame/tokenizers 的独立语义验证、HexEditor 的结构可视化、MoonMarkMind 的即用体验、raft 的故障不变量。这里借鉴可验证的工程方法，不照搬 UI 或用代码量判断优劣。

## 3. 核心设计取舍

- MoonBit 负责 DICOM、策略、关联关系与验证；浏览器/Native/Python 只承担平台 I/O、界面和既有提供方权限。
- SDK 默认封闭集合，转换结果全部校验成功后才返回。输入顺序与输出顺序一致；无隐式外部引用放行。
- UID seed/日期偏移由宿主显式提供，演示使用固定合成值；SDK 不伪装成安全随机源或跨作业身份数据库。
- 浏览器实验室先服务学习与合成复现；真实影像的受控使用、审核/签名/交付仍沿原宿主流程。任何未来文件导入必须显式标注本地私有视图并经过预算与公开输出检查。
- 历史兼容 `src/` 入口保留；新文档优先使用公开接口。独立消费能力以实际编译/运行证明，生成接口中的内部类型名称不单独当作失败标准。
- 不自动联系社区用户、医院或主办方，不虚构采用案例。授权数据/真实使用方是现场证据的输入，不是能由程序生成的结果。
