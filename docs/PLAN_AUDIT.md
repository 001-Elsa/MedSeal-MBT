# 深化方案逐项核对

核对对象：[《MedSeal-MBT 深化迭代与参赛方案》](ITERATION_PLAN.md)。基线为
`bb7e895` / 0.1.1，交付版本为 0.2.0 候选版。

**结论：原方案没有逐项全部完成。** 已完成研究模式的核心关联转换主线，
但实施时缩小了策略和标准支持范围，一部分原定工程验收也仍缺证据。
“A–D 已完成”只能描述下表所列核心子集，不能代表原方案的全部交付门槛。

## 原方案本来就列为后续扩展的事项

跨作业稳定映射/密钥持久化、DT/TM 时区及组合语义、更多传输语法、
压缩像素、OCR/PACS/DICOMweb 和 Web 后台，不属于当前第一版核心验收。
它们没有实现，应继续明确列为后续扩展；不能为了宣称“全部完成”而将其勾选。

## 十个验收场景的覆盖情况

1. 多患者、多 Study/Series/实例分组：独立合成集合已覆盖。
2. 主 UID、引用、File Meta 同步及顺序变化：独立检查与单元回归已覆盖。
3. 嵌套身份字段、动作路径及公开报告隐私：已覆盖所列合成标记。
4. 标准 UID 保留已覆盖；研究模式核心身份/引用字段限定单值，不是任意多值 UI 的完整覆盖。
5. 完整 DA 日期间隔、闰日、跨年、非法及越界：已覆盖。
6. 前导区、File Meta、文件名与嵌套合成标记：已覆盖所承诺清理位置。
7. 字节保真、Unicode 与不支持编码拒绝：已覆盖所列场景。
8. 外部/重复引用、冲突、未知角色和有界读取：部分覆盖；每个资源上限与未知输入类别仍需系统化矩阵。
9. 报告预检失败和计划后输入变化已覆盖；执行中写盘故障、硬中断、恢复和并发验收未完成。
10. 再次执行同一计划及重复处理标记拒绝：已覆盖。

上述判断对应源码、测试及 `docs/evidence/local-verification.json`、
`docs/evidence/github-verification.json`。
通过 91 项 Native 和其他后端各 53 项测试，不等于通过原方案每个验收场景。
