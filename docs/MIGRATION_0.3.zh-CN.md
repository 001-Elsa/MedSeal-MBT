# 0.3.0 迁移与故障恢复

本文保留 0.2.x → 0.3.0 的版本迁移语境；当前 0.4.1 → 0.5.0 的新增接口、implicit接受与写出语义见[0.5迁移](MIGRATION_0.5.zh-CN.md)。

## 从 0.2.x 升级

1. 保存原运行包、规则指纹、作业目录和审核记录；不要覆盖原目录。
2. 在新目录安装 `001-Elsa/medseal@0.3.0`，运行 `tools/doctor.py --json`。
3. 对封存的**原始输入**建立新作业，重新执行预检、转换、复核和签名。
4. 比较新旧公开报告与输出摘要；人工确认后才允许交付。

旧缓存不会跨版本复用，旧审核不会自动变成新版本审核。重新处理已经转换的影像会造成重复日期偏移，必须从原始封存输入开始。

## 固定失败处理

| 现象 | 操作 | 禁止操作 |
| --- | --- | --- |
| `MEDSEAL-E...` 规则/字典不兼容 | 记录代码、版本、输入摘要，回到原运行包或建立新计划 | 修改错误文本绕过拒绝 |
| 预检发现链接、硬链接或超预算 | 按报告中的对象 ID 修复输入后重新扫描 | 删除失败对象后宣称整批通过 |
| 接收端中断 | 重新验证完整签名包，再按适配器重试 | 上传未经复核的部分文件 |
| registry 版本不存在 | 保留旧版本，修复发布流程后重试 | 用本地源码替代 registry 成功 |

所有迁移报告只保存匿名对象 ID、计数、版本和指纹。原值、患者标识、密钥和本机路径不得进入公开报告。

> 文档核对：迁移流程是可重复的工程操作，不是医疗验证或生产认证。见[稳定 API](API_COMPATIBILITY.zh-CN.md)与[恢复说明](RECOVERY.md)。
