# 0.6.0 迁移说明：可验证数据变换证据

0.6.0 把项目默认入口从 DICOM 数据转换改为领域无关的变换证据库。这个变化是项目定位变化，不是把旧医疗代码改名后继续作为新功能计算。

## 新入口

导入：

```moonbit
import {
  "001-Elsa/medseal/api/evidence" @evidence_api,
}
```

核心类型为 `Plan`、`OutputRecord`、`SourceRef`、`Receipt` 和 `Verification`。调用方声明计划和摘要，为输出记录提供输入来源，然后在独立进程中调用 `Receipt::verify`。

```sh
./tools/moon-local run --target native examples/evidence
```

## 语义

- `input_digest` 绑定实际输入快照；输入发生变化时验证失败。
- `rule_digest` 绑定调用方的规则计划；计划变化时验证失败。
- `output_digest` 绑定实际输出；输出变化时验证失败。
- `SourceRef` 记录每条输出记录的来源和变换步骤。
- 收据验证通过只说明这些证据彼此一致，不说明数据匿名、业务正确、合规或可以公开发布。

## 有意不提供的功能

证据核心不负责通用清洗、脱敏、随机数据生成、关系闭包提取、失败用例最小化或实时 CDC。这些功能若由调用方执行，应作为外部变换步骤写入计划和来源记录，不应伪装成核心已经实现。

## DICOM 兼容面

旧版 DICOM 解析、验证、JSON 交换和转换代码仍保留在仓库，供历史回归和可选兼容使用。它们不再是 0.6.0 默认项目故事，也不计入证据核心新增能力。需要旧入口的消费者应继续按原模块和原版本验证，不要只凭 0.6.0 的收据 API 推断 DICOM 隐私或发布安全。
