# Third-party and data provenance

MedSeal-MBT is an original MoonBit implementation. It is not a port of another
DICOM library and contains no copied DICOM parser or de-identification code.

## Test and sample data

Every `.dcm` file under `samples/` is generated by
`tools/generate_samples/main.mbt`. The fixtures contain invented names,
identifiers, UIDs, institution text, and tiny synthetic Pixel Data byte arrays.
They do not originate from a patient, hospital, scanner, public clinical
dataset, or third-party DICOM project. Regeneration instructions and the role
of every fixture are documented in `samples/README.md`.

## Generated interfaces and AI assistance

`pkg.generated.mbti` files are generated by the MoonBit toolchain using
`moon info` and are committed so public interfaces can be reviewed. AI tools
assisted implementation, review, tests, and documentation; the repository
owner remains responsible for behavior, scope, licensing, and submitted data.

## New verification and standard references

pydicom 3.0.1 (MIT, https://github.com/pydicom/pydicom) is a development-only
independent parser and synthetic fixture generator. It is not used by the
MoonBit runtime. Generated data contains no clinical records.

`src/storage/entropy.c` is original project code that only calls OS random
facilities. It implements no cryptographic algorithm. gmlewis/sha256 provides
integrity hashes and is checked against standard vectors.

Research-v1 rules reference DICOM PS3.15 Annex E. No DICOM implementation is
copied, and complete confidentiality-profile conformance is not claimed.

Strict-v1 dictionary data is generated from the MIT-licensed pydicom 3.0.1
dictionary. The subset source and generator are committed under resources/rules
and tools/generate_strict_dictionary.py; generated data membership does not
imply complete IOD/Profile validation. The upstream MIT license is retained in
resources/licenses/pydicom-LICENSE. The independent official dicom3tools binary
is a development tool installed outside this repository, not a runtime or
redistributed package dependency.

## Enterprise private adapter and delivery dependencies

Python 3.12 standard library provides SQLite, local POSIX locking and filesystem
coordination. cryptography50.0.2 (Apache-2.0 OR BSD-3-Clause;
https://github.com/pyca/cryptography) provides HKDF/HMAC-related key derivation,
AES-256-GCM and Ed25519. Python hmac/hashlib use the interpreter's vetted provider.
The adapter does not implement cryptographic primitives or parse/transform DICOM.
Fixed offline wheels include cffi2.1.1 (MIT) and pycparser3.0 (BSD-3-Clause); wheel
license texts and SHA256 entries are included in generated installation packages.
The native SHA dependency remains an integrity hash, not the identity encryption
or signature provider. Development dciodvfy/pydicom executables are not bundled.
The MoonBit core/runtime is included in native compiled binaries under its Apache-2.0
license; compiler release0.10.14+7d59c7ec9 is recorded in the generated SBOM.

resources/rules/standard-facts-2025e.json stores selected interoperability facts
(selected tag codes and MIT-pydicom VR/VM tokens) with fixed official PS3.6/PS3.15
URLs and source hashes, not the standard document, explanatory prose, illustrations
or a complete table reproduction. This factual subset is used to check the
implementation's dictionary and policy, and is not labeled as NEMA endorsement,
a complete confidentiality profile or a grant to redistribute the standard under
Apache-2.0. Project-specific decisions and synthetic fixtures are original;
The former PS3.15 bulk action-code table was removed during the contest audit remediation; the generator now retains only selected reference tags, source links and hashes, never action table cells. The official website terms (https://www.dicomstandard.org/dicom-terms-conditions, sections 1.1/1.2) restrict reprinting/distributing copyrighted works; no written permission to reprint is claimed. The strict dictionary subset separately derives from MIT-licensed pydicom, whose
license is retained. Downloaded official HTML/PDF remains outside release archives.
The standard's public availability alone is not treated as an unrestricted
reproduction license; any future redistribution of standard text/full tables
requires an explicit rights basis and retained original notices.
